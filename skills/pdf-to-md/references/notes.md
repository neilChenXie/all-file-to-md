# PDF 文本层提取与表格还原——方法论与踩坑记录

本文件是 `pdf-to-md` skill 文本层直提路线（SKILL.md 步骤3）的细节参考，按需加载。

## 1. 文本层检测

- 用 PyMuPDF 逐页 `page.get_text()` 统计字符数即可，无需 OCR 试探。
- 判定阈值：总字符 > 100 且 非零文本页占比 ≥ 50%。
- 抽样内嵌字体（前 5 页 `get_fonts()`）可佐证：出现 SimSun/SimHei 等子集字体（如 `AAZLDD+SimSun`）说明是原生导出；扫描件通常无字体或只有图片。
- 生成器元数据（producer/creator）有参考价值：Adobe Illustrator / Word / WPS 导出的必带文本层。

### 1.1 乱码检测（有文本层 ≠ 可直提）

字体缺 ToUnicode 映射、编码转换错误时，能提取到大量字符但全是乱码；直提会产出满篇无效内容，必须放弃文本层、改走图片 OCR 路线。逐页对 `page.get_text()` 结果评估，命中任一特征即该页乱码（检出函数 `garbled_signals()` 固化在 check_textlayer.py / extract_pdf_to_md.py，两处实现保持一致）：

1. **无效字符占比 ≥ 5%**：替换符 `U+FFFD`、私用区字符（U+E000–U+F8FF）、控制符（含 C1 区 0x80–0x9F）、`(cid:N)` 占位符。
2. **Latin-1 补充区（U+0080–U+00FF）字符占比 ≥ 25%**：UTF-8/GBK 字节流被按 Latin-1/cp1252 解码的典型产物（如 `ä¸æ–‡`）；正常中英文文档该区间字符占比极低，该区间常见的合法符号（`· × ÷ ± ° § µ ¥ £ © ®`）已从分子排除。
3. **单一非 ASCII 字符占比 ≥ 40%（页内非空白字符 ≥ 50）**：字体映射错乱时整段文本落到同一码位（满屏 `ÿ`、`□` 等）；ASCII 字符不参与该判定（避免误伤表单页复选框 `n/o`、目录页引导点 `.`），中文常用标点也已排除。
4. **出现经典乱码串"锟斤拷"**（UTF-8 替换字节被按 GBK 解码的产物）。

判定口径：仅对有 ≥30 个非空白字符的页做评估；**≥50% 的有效内容页乱码 → 整份判为不可直提**（check_textlayer.py 退出码 3；extract_pdf_to_md.py 同样中止且不产出文件），改走图片 OCR 路线；**个别页乱码（<50%）→ 仍走直提**，但这些页不参与正文字号统计、不入正文，提取脚本在对应分节留下 `<!-- 本页文本层乱码… -->` 注释，由 3.2 导出 PNG 用图像识别补齐后替换注释。

## 2. 表格还原流水线（已固化在 extract_pdf_to_md.py）

检出 → 四层过滤 → 覆盖校验 → 折行合并，顺序不能乱：

1. **列数过滤**：`col_count > 12` 的是"无竖线两栏正文被横线切割"的碎片（实测条款区会检出 13~37 列伪表格）。
2. **伪表格过滤**：`非空列占比 ≤ 0.5 且最长单元格 ≤ 60 字`。特征依据：正文被框线/横线围住时，单元格文本恰为正文行宽（中文约 34 字/行），且半数以上列全空。临界个案靠长度区分：真表单（如转账授权表 0.50 占比 + 100 字单元格）保留，伪表格（0.50 + 54 字）过滤。
3. **碎片丢弃**：bbox 被另一个更大表格完全包含的"表格"是误检碎片。
4. **覆盖校验（兜底）**：表格 bbox 内的文本行中心点必须全部落在 `t.cells`（含合并大格）的某个单元格 bbox 内，否则该页全部回退纯文本。

### 覆盖校验的关键坑

- **禁止用字符数对比校验**：合并单元格的延续格 `extract()` 返回 `None`，字符数会被低估，导致把"完美表格"误判为丢字回退（实测 53x7 清单表 164 行文本实际 0 丢字）。
- `t.cells` 返回该表所有单元格矩形（含合并后的大格），用行中心点判断覆盖，容差 1pt。

### 折行延续行合并

- 单元格内折行的文本会被 `find_tables` 拆成独立的"空序号行"（首列为空），渲染后变成空行穿插。
- 合并方向判定：碎片行某列有值时，若"前行该列非空且后行该列空 → 归后行；前行空后行非空 → 归前行"，同列多碎片用 `<br>` 连接。物理上折行文本跨在两行之间，只看"并到上一行"会错。
- 仅当首列在多数数据行非空（序号/标签列表）时才启用合并，避免把普通空首列表格误并。

## 3. 页脚处理

- 页脚可能有**两种排版顺序**（同一份 PDF 内）：奇数页"打印日期：… 第 x / y 页"，偶数页"第 x / y 页 … 打印日期"。正则必须同时匹配 `第x/y页` 前缀、`打印日期` 前缀、以及两者同行的情况，否则一半页面漏检。
- 另识别**居中纯页码行**（`12`、`- 12 -`、`— 12 —`）：仅当水平居中（行中心在页宽 30%~70%）且位于页顶/页底 10% 边缘带时移除并计页码；此类页脚不含总页数，doc_pages 需其他来源提供。
- 页码映射（文档页码 vs PDF 页码）通常是恒定偏移（如封面+客服页不计入 → 偏移 -2），用全部页脚逐页验证后写入提取说明，方便与纸质页码互查。

## 4. 标题提升（已通用化，不依赖领域词汇）

- 两层判定，启发式优先：
  1. **字号/加粗启发式**：预扫描全文行字号分布，以正文众数字号为基准——行字号 ≥ 众数+1pt 的短行 → `###`（进目录）；整行加粗（加粗字符占比 > 0.8，字体名兼容 latin Bold/Black/Heavy 与 mojibake 还原后的"黑体/粗体"）且不小于正文字号的短行 → `####`。
  2. **通用中文文档模式**（归一化空格后整行匹配）：第X章/节/篇、附录/附件、附表N：、引言/前言/概述/总则 → `###`；目录、第X部分、`1、xx`/`N．xx` 编号小标题 → `####`。
- 防误判四招：长度上限（≤45 字）；正文开头词黑名单（包括/及/详见…）；句读排除（含逗号/句号/分号/问号/"详见"/"了"的行是正文，顿号除外——编号小标题依赖它）；目录条目排除（含引导点 `..`/`……` 的行不提升，章节/附录模式尾部字符类排除数字与点，防"第三章 总则......12"误判）。
- 版式特殊文档用 `--title-pats` 追加正则（可多次传入），**显式模式优先且不受防误判约束**（宽松正则的误判由调用方负责）。
- 历史版本曾内置保险单证词表（投保单/保险单/保障计划一览表等，源于一次 74 页电子保单实战定制），2026-09 起移除，改由启发式 + 显式模式覆盖。

## 5. 已知限制

- 两栏版式（左窄栏小节标题 + 右宽栏正文）按 y,x 排序拼接，个别换行处文字顺序有细微出入；`pymupdf_layout` 包可能改善（未验证）。
- 无框线表格（如保险单主表、图片化 TNM 分期）检不出，保持纯文本流，内容不丢。
- 合并单元格在 Markdown 中以空单元格表示（Markdown 无原生合并语法）。
- 提取结果含身份证号、保险单号等敏感信息，对外分享前须脱敏。

## 6. Windows 环境坑

- Git Bash heredoc 传 Python 脚本时 `\\` 会被折叠成 `\` —— 长脚本一律写成 .py 文件执行，脚本内用 `chr(92)` 生成反斜杠。
- 运行时加 `-X utf8`（或设 `PYTHONUTF8=1`）避免 GBK 编码错误。
- 按用户约定：先向上查找 `.venv`/`venv` 直到盘根，找到则用其 python；没有则在盘根创建。
