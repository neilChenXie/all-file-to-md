## Workflow：检测 → 分发

本 skill 仅支持一种输入方式：**PDF 文件**（用户直接指定一个 PDF 文件）。

占位符约定：

- 【输入文件】：用户指定的 PDF 文件完整路径
- 【输入文件所在目录】：该 PDF 所在目录
- 【输入文件名】：PDF 文件名去掉扩展名（如 `report.pdf` → `report`）
- 【清洗后输入文件名】：将【输入文件名】中的空格及其他非法字符（`\ / : * ? " < > |` 及控制字符）替换为下划线 `_` 得到（如 `SFT 0028-2018 智慧监狱 技术规范` → `SFT_0028-2018_智慧监狱_技术规范`）
- 【skill目录】：本 skill 所在目录

流程总览（先执行步骤 1、2，再按检测结果分发）：

```
步骤1 安装依赖（requirements.txt）
   ↓
步骤2 检测 PDF 是否有文本层（check_textlayer.py）
   ├─ 退出码 0（有文本层，电子版）→ 步骤3 加载 pdf-text-to-md skill 执行文本层直提路线
   ├─ 退出码 3（有文本层但为乱码）→ 步骤3 加载 pdf-img-to-md skill 执行图片 OCR 路线
   └─ 退出码 1（无文本层，扫描件）→ 步骤3 加载 pdf-img-to-md skill 执行图片 OCR 路线
```

### 步骤1：安装依赖

1. 依赖清单见本 skill 目录下的 `requirements.txt`（pymupdf），安装命令：

   ```bash
   pip install -r <skill目录>/requirements.txt
   ```

   国内网络下 pip 默认源可能长时间无响应，直接改用镜像：

   ```bash
   pip install -r <skill目录>/requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
   ```

2. 检测脚本启动时会自查依赖，缺依赖时打印安装提示并退出；按提示补装后重跑即可。子 skill 所需的额外依赖（pillow、numpy）由其自身 requirements.txt 声明，在加载子 skill 后按其步骤1安装。

### 步骤2：检测 PDF 是否有文本层（必做，不得跳过）

运行检测脚本，根据退出码分流：

```bash
python -X utf8 <skill目录>/scripts/check_textlayer.py "【输入文件】" [--json]
```

- **退出码 0（有文本层）**：输出会给出页数、可提取字符总数、非零文本页占比、抽样字体、零文本页列表。走**步骤3 分发 → pdf-text-to-md**。
- **退出码 1（无文本层）**：属扫描件，走**步骤3 分发 → pdf-img-to-md**，不要对扫描件强行文本提取。
- **退出码 2（执行出错）**：文件无法打开等异常，抛出错误并提示用户检查输入路径与文件。
- **退出码 3（有文本层但为乱码）**：字体缺 ToUnicode 映射、编码错乱等导致提取出的文字不可读，且**乱码页占有效内容页 ≥5%**（输出会列出乱码页与命中特征）。走**步骤3 分发 → pdf-img-to-md**，不得强行文本提取。
- 加 `--json` 可获取机器可读结果（含 `textlayer_garbled`、`garbled_pages` 字段）。
- **记录检测上下文（分发时必须一并带入子 skill）**：
  - 页数、零文本页清单：若多数页有文本、仅个别页为 0 字符（封面/封底/整页扫描图），属混合型 PDF，仍分发 pdf-text-to-md，但其步骤3 回退需要零文本页清单；
  - 个别乱码页清单（占比 <5%，整体仍可直提）：同样带入 pdf-text-to-md 的步骤3 回退；
  - 乱码检测的命中特征与原因（退出码 3 时）：带入 pdf-img-to-md 作为路线确认依据。

### 步骤3：分发（只分发，不执行转换）

根据步骤2 的退出码，加载对应 skill 并执行其流程：

- **退出码 0** → 加载 `pdf-text-to-md` skill，执行其文本层直提流程；带入步骤2 的检测上下文（页数、零文本页清单、个别乱码页清单）。
- **退出码 1（无文本层）或 3（文本层乱码）** → 加载 `pdf-img-to-md` skill，执行其图片 OCR 流程；带入页数与乱码原因。
- **退出码 2** → 不分发，抛出错误并提示用户检查输入路径与文件。

本 skill 只做检测与分发，**不得**直接执行任何转换步骤（脚本提取、PNG 导出、子agent识别等均属子 skill 职责）。子 skill 的输出目录、错误处理与实践经验见其各自 SKILL.md 的相应章节。

## 错误处理

- 用户指定的 PDF 不存在、不是 PDF、损坏或无法打开（检测脚本退出码 2），应当抛出错误并提示用户检查输入路径、文件格式。
- 缺少依赖（检测脚本会提示缺 PyMuPDF），按步骤1安装后重跑。
- 路线内错误（提取中止、导出失败、识别失败、坐标越界等）由对应子 skill 处理，见其 SKILL.md 的错误处理章节。
