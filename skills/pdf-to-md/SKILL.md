## Workflow：PDF → Markdown 双路线流程

本 skill 仅支持一种输入方式：**PDF 文件**（用户直接指定一个 PDF 文件）。

占位符约定：

- 【输入文件】：用户指定的 PDF 文件完整路径
- 【输入文件所在目录】：该 PDF 所在目录
- 【输入文件名】：PDF 文件名去掉扩展名（如 `report.pdf` → `report`）
- 【清洗后输入文件名】/【清洗后图名】：将【输入文件名】/【图名】中的空格及其他非法字符（`\ / : * ? " < > |` 及控制字符）替换为下划线 `_` 得到（如 `SFT 0028-2018 智慧监狱 技术规范` → `SFT_0028-2018_智慧监狱_技术规范`）
- 【skill目录】：本 skill 所在目录（`<skill目录>` 即本文件所在目录）
- 【图片目录】：【输入文件所在目录】/tmp_【清洗后输入文件名】/（仅步骤4图片路线使用；每个 PDF 独占一份，同一目录下多份 PDF 并行处理互不干扰）

流程总览（先执行公共步骤 1、2，再按检测结果二选一；混合型 PDF 以步骤3为主、零文本页/乱码页按 3.2 回退）：

```
步骤1 安装依赖（requirements.txt）
   ↓
步骤2 检测 PDF 是否有文本层（check_textlayer.py）
   ├─ 退出码 0（有文本层，电子版）→ 步骤3 文本层直提路线（脚本提取 + 表格还原）
   ├─ 退出码 3（有文本层但为乱码）→ 放弃文本层提取，走步骤4 图片 OCR 路线
   └─ 退出码 1（无文本层，扫描件）→ 步骤4 图片 OCR 路线（导出PNG + 子agent识别）
```

### 步骤1：安装依赖

1. 依赖清单见本 skill 目录下的 `requirements.txt`（pymupdf、pillow、numpy），安装命令：

   ```bash
   pip install -r <skill目录>/requirements.txt
   ```

   国内网络下 pip 默认源可能长时间无响应，直接改用镜像：

   ```bash
   pip install -r <skill目录>/requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
   ```

3. 各脚本启动时会自查依赖，缺依赖时打印安装提示并退出；按提示补装后重跑即可。

### 步骤2：检测 PDF 是否有文本层（必做，不得跳过）

运行检测脚本，根据退出码分流：

```bash
python -X utf8 <skill目录>/scripts/check_textlayer.py "【输入文件】" [--json]
```

- **退出码 0（有文本层）**：输出会给出页数、可提取字符总数、非零文本页占比、抽样字体、零文本页列表。走**步骤3 文本层直提路线**。
- **退出码 1（无文本层）**：属扫描件，走**步骤4 图片 OCR 路线**，不要对扫描件强行文本提取。
- **退出码 2（执行出错）**：文件无法打开等异常，抛出错误并提示用户检查输入路径与文件。
- **退出码 3（有文本层但为乱码）**：字体缺 ToUnicode 映射、编码错乱等导致提取出的文字不可读（输出会列出乱码页与命中特征）。**直接放弃文本层提取，走步骤4 图片 OCR 路线**，不得强行文本提取。
- 加 `--json` 可获取机器可读结果（含 `textlayer_garbled`、`garbled_pages` 字段）。
- **记录零文本页清单**：若多数页有文本、仅个别页为 0 字符（封面/封底/整页扫描图），属混合型 PDF：仍走步骤3，但零文本页需在 3.2 单独回退为图像识读。同理，若输出列出**个别乱码页**（占比 <50%，整体仍可直提），这些页也在 3.2 回退为图像识读。

### 步骤3：文本层直提路线（有文本层时执行）

将原生导出 PDF（自带文本层）的全文按页提取为结构化 Markdown：页码分节、章节标题提升、可跳转目录，并把带框线表格还原为 Markdown 表格（含合并单元格、折行单元格处理）。纯文本层直提，非 OCR，内容零丢失。

#### 3.1 文本流提取 + 表格还原

```bash
python -X utf8 <skill目录>/scripts/extract_pdf_to_md.py "【输入文件】" [-o "【输入文件所在目录】/【输入文件名】.md"]
```

- 默认输出：与 PDF 同目录同名 `.md`。
- 脚本自动完成：逐页 `## 第 N 页` 分节、页脚（页码/打印日期）识别与移除、页码映射验证、章节标题提升（`###`/`####`）、文首可跳转目录、带框线表格还原为 Markdown 表格（伪表格过滤 + 覆盖校验兜底 + 折行单元格合并）。
- 脚本结束会打印：输出路径、还原表格数、校验回退页、乱码回退页、页脚命中数、章节标题数。
- **乱码守卫**：脚本直提前先逐页检测文本层乱码（替换符/私用区字符/(cid:) 占位符、Latin-1 区字符占比过高、单一字符高度重复、经典乱码串"锟斤拷"）。若乱码页占有效内容页 ≥50%，脚本**以退出码 3 直接中止且不生成输出文件**——此时放弃文本层提取，改走步骤4图片 OCR 路线；个别乱码页（<50%）不入正文，仅在对应 `## 第 N 页` 分节留下 `<!-- 本页文本层乱码… -->` 注释，按 3.2 用图像识别补齐后替换该注释。

#### 3.2 混合型 PDF 的零文本页/乱码页回退（仅当步骤2检出零文本页或乱码页时）

1. 仅导出零文本页/乱码页为 PNG（以零文本页为第 3、5 页为例）：

   ```bash
   python -X utf8 <skill目录>/scripts/pdf_to_png.py "【输入文件】" --start-page 3 --end-page 3
   ```

   多页时按连续区间逐段调用；PNG 输出到【图片目录】，命名规则同 4.1。

2. 对每张回退页 PNG，按 4.4 的识别要求（含对开页拆分、含图标记规则）用多模态子agent识别，输出临时 md 后并入主 md 对应的 `## 第 N 页` 分节内（若该分节留有 `<!-- 本页文本层乱码… -->` 注释，用识别出的内容替换该注释）；如这些页含可提取插图，可继续按 4.8 处理。

#### 3.3 验证与交付

1. 用 `present_files` 交付 .md 文件。
2. 抽查 2–3 个关键页的渲染效果（表格页、条款首页）确认无乱序、无伪表格残留。
3. 在回复中报告：页数、还原表格数、页码映射偏移、回退页（零文本页/乱码页，如有；乱码回退页须已按 3.2 用图像识别补齐）。

#### 文本层路线要点（复杂版式定制实战记录）

extract_pdf_to_md.py 覆盖常见版式；以下要点实测于 74 页 / 8.7 万字电子保单（脚本一次跑通、零 OCR 误差），当文档版式超出脚本能力、需要定制处理时参考：

1. **三栏切分**：合同/条款类正文常为「编号栏 / 名称栏 / 正文栏」三栏版式。用 `get_text('rawdict')` 取**字符级**坐标，按 x 分栏（本例编号 x<100、名称 100≤x<199、正文 x≥199）。**正文栏左边界取实测众数减 2**（本例实测 201.6 → 取 199），否则正文会被误判为名称，导致标题行被正文灌满。
2. **名称可越界**：名称栏最右可达 ~236（如"合同效力的中止及恢复"），不能用固定 200 一刀切。判定规则改为：span 起点 x≥正文左界 → 正文；否则为编号/名称；仅当"跨栏合并 span"（x1>250，名称与定义首行被合成一个 span，本例仅 1 处）才在名称与正文之间的**空格处**切开。
3. **上下标自成一行**：`10^9/L` 这类上标在 PyMuPDF 中是**独立 line**，且 y0 可能比主行更小，按 (y,x) 排序会把正文顺序打乱（实测出现"新生儿 Hb＜100g9/L"，正确为"…g/L），PLTS＜100×109/L"）。解决：按 **span 行底 y1 排序**，并按"纵向重叠"归并同一视觉行（`sp.y0 <= row.y1-1 且 sp.y1 >= row.y0+1`），行内再按 x 排序。
4. **标题跨多行 + 正文同行**：小节名称可能换行 2~8 行且与正文首行同一 y。做法：标题名持续累积"只要还没遇到下一个编号行"，**标题与其下段落延迟输出**（用 pending head + items 缓冲，遇到下一个编号行时整块落盘），否则标题名会被截断或正文被吞。
5. **段落拼接规则**：`上一行满行（x1≥右边界-20） 且 行距≤15（正文行距 13~14，段间距 16~17） 且 下一行不匹配段首模式 且 上一行不以"："结尾`。段首模式：`（n）`、`①`、`a)`、`^\d+[、.](?!\d)`（注意加 `(?!\d)`，否则 "13.1)" 会被误判）、`注：`、`一、`、`（一）`。
6. **跨页断裂**：正文段落直接跨页续接（不做任何页间处理即可），但**表格跨页必须合并**（现金价值表、利益演示表、健康告知表）——脚本不处理跨页表格，需在合并/校对阶段人工或脚本合并。
7. **加粗 = 黑体**：源文档的重点内容用"黑体"字体（注意字体名常为 mojibake，需 `s.encode('latin-1').decode('utf-8')` 还原后判断），转换时映射为 `**…**`；**纯标点的独立加粗段**（如 `**。**`、`**”**`）要并入相邻段，否则满篇噪声。
8. **表单页 n/o 是复选框**：`Wingdings` 字体的 `n`=■（已勾选）、`o`=□（未勾选），页内说明通常写作"表格中使用"■"代表投保人已经勾选的信息"。按列位置还原成"■是 □否"这类可读文本。
9. **Coverage 校验（替代逐页人工核对，必做）**：用 `difflib.SequenceMatcher(None, 源页文本, 全md文本).get_matching_blocks()` 计算**每页匹配率**，逐页输出 <98.5% 的页并打印**未匹配片段**。合法的低分页只有"有意重排"的页（目录页、表单页、利益演示表页）；正文页低于 99% 一定有丢失，按未匹配片段定位规则缺陷。另外用"数量声明自检"做完整性证明：条款中"本合同所定义的X疾病共有N种"与 `X.` 编号条目数比对（本例 55/30/135/20/33 全部吻合）。
10. **任务量参考**：74 页电子版保单，文本层路线约 20~30 次工具调用、脚本一次成型；同文档走图片 OCR 路线需 15 批 × 5 子agent，且受 429 配额限制（见图片路线实践经验"429 兜底"条）。

#### 参数定制

标题识别已通用化，处理任何带文本层 PDF 无需改代码：脚本先按**字号/加粗启发式**（预扫描全文，以正文众数字号为基准——字号显著更大的短行 → `###` 进目录，整行加粗的短行 → `####`），再按**通用中文文档模式**（第X章/节/篇、附录/附件、附表N：、引言/前言/概述/总则、目录、`1、xx` 等编号小标题）兜底。版式特殊识别不足时，用 `--title-pats` 追加标题正则兜底（可多次传入；显式模式优先且不受防误判约束，宽松正则的误判由调用方负责）：

```bash
python -X utf8 <skill目录>/scripts/extract_pdf_to_md.py "【输入文件】" --title-pats '^保障计划一览表$' --title-pats '^.{10,40}条款$'
```

伪表格过滤阈值（非空列占比 0.5 / 最长单元格 60 字 / 列数上限 12）一般无需改动。

表格还原流水线的判定依据、覆盖校验的正确姿势（禁止字符数对比）、页脚双格式、标题防误判规则等细节见 `references/notes.md`——在排查提取质量问题时加载该文件。

#### 已知限制

- 两栏版式（左窄栏标题 + 右宽栏正文）按位置排序拼接，个别换行处文字顺序可能有细微出入。
- 无框线表格与图片化内容检不出，保持纯文本流（内容不丢）。
- 合并单元格以空单元格表示（Markdown 无原生合并语法）。
- 提取结果可能含身份证号、账号等敏感信息，对外分享前提醒用户脱敏。

### 步骤4：图片 OCR 路线（无文本层/扫描件时执行）

适用对象：扫描件/图片型 PDF。先逐页导出为 PNG（存放在【图片目录】下），再分批用多模态子agent识别合并成 md，最后按需提取插图。

#### 4.0：删除【图片目录】

检查【图片目录】（即【输入文件所在目录】/tmp_【清洗后输入文件名】/）是否存在，若存在则删除该目录及其内容，确保后续步骤中导出的图片不会与旧文件冲突。该目录与 PDF 文件一一对应，同一目录下多份 PDF 并行处理时只清理各自的临时目录，不会相互影响。

#### 4.1：PDF 转 PNG 图片

用户指定 PDF 文件后，先执行本步骤，将 PDF 逐页导出为 PNG 图片：

1. 调用脚本 `scripts/pdf_to_png.py`（位于本 skill 目录下，即 `<skill目录>/scripts/pdf_to_png.py`），执行命令示例：

   ```bash
   python -X utf8 <skill目录>/scripts/pdf_to_png.py "【输入文件】" --dpi 200
   ```

   - 脚本会自动创建【图片目录】，图片输出到该目录。
   - 图片命名规则：【清洗后输入文件名】_NN.png（如 report_01.png、report_02.png，页码按总页数自动补零，满足 4.2 的前缀判断规则）。
2. 若运行时报错提示缺少 PyMuPDF 依赖，按步骤1安装依赖后重新运行。
3. 导出完成后，核对【图片目录】下 PNG 图片数量与 PDF 页数一致，然后以【图片目录】作为图片来源，继续执行 4.2。

注意事项：

- 扫描件建议加 `--dpi 300` 提高识别精度；普通电子版 PDF 用默认 `200` 即可。
- 局部调试可配合 `--start-page` / `--end-page` 仅导出部分页。

#### 4.2：判断图片来源与对开页检测

1. **同一文件校验**：读取【图片目录】下的图片文件列表，检查图片是否来自同一份文件（通常命名为【清洗后输入文件名】_01.png、【清洗后输入文件名】_02.png 等）。如果图片文件名称不符合规则，或者无法判断是否来自同一份文件，则抛出错误并提示用户检查图片文件是否来自同一份文件。
2. **模型能力确认**：需要先确定用户使用的大模型具备图片识别能力，否则无法进行图片内容识别。
3. **对开页检测**：选取 3 张图片进行预处理检测，判断是否为扫描的对开页文档（即双页并排扫描）：
   - **标记策略**：如果检测到图片为对开页，则在该图片的处理标记中注明"对开页/双页并排"，并记录需要拆分为左页和右页分别识别。
   - **兼容处理**：即使用户未明确告知，子agent也应当主动识别图片是否为对开页结构，并据此调整处理策略。

#### 4.3：创建空文档

在【输入文件所在目录】/ 目录下，创建一个空的md文档【输入文件名】.md。

#### 4.4：调用子agent处理文件

从【图片目录】读取图片：启动5个子agent，按照图片名称的排序（从小到大），每个子agent从【图片目录】读取一张图片的内容，并输出到【图片目录】/【图片名】.md。

子agent处理时需要注意以下事项：
- 识别图片内容，提取文本、表格、公式等信息，并按原文及原有格式输出到md文件中。
- 识别表格时，尽量保持表格的原有结构和格式，必要时进行格式优化。
- 忽略图片中的水印、页眉页脚、页码等非内容信息。
- **含图标记（4.8 的前置输入）**：如果本页含图片，识别完本页内容后，在临时md文件的**有图片的位置**追加一行标记，格式为：
  - 本页含可提取的插图（示意图、架构图、拓扑图、照片、统计图表等，区别于装饰性水印）：`<!-- 本页含图: 图名（若图注/图中已有明确名称则用其名称，如"图1 智慧监狱总体架构"；无名称可用一句话描述内容，如"网络拓扑示意图"） -->`
  - 仅需一句话标记，**不要**输出定位坐标、不要裁剪、不要猜测边界。
- **对开页（双页并排）处理**：如果图片属于扫描的对开页文档（即一张图片中包含左右两页内容），需要按以下规则处理：
  - 首先识别图片中的装订线/中缝位置，以此作为左右分页的基准线。
  - 将图片内容拆分为**左页**和**右页**两部分，分别识别。
  - 识别时先读取左页内容（按从左到右、从上到下的阅读顺序），再读取右页内容。
  - 如果左右两页的表格内容存在跨页关联（如表头相同、内容连续），需在输出时进行合并处理，确保表格完整性。
  - 输出到临时md文件时，按左页在前、右页在后的顺序输出，保持文档的原始阅读顺序。

#### 4.5：合并子agent输出

将 4.4 的子agent输出的 5 个【图片名】.md 文件（位于【图片目录】），合并到【输入文件所在目录】/【输入文件名】.md 文件中，合并时评估是否有表格使用相同的表头等情况，需要进行格式优化。

合并时需要注意以下事项：
- 保持原有的内容顺序，确保合并后的md文档内容完整。
- 不需要补充页码、页眉页脚等非内容信息。
- 对于表格，表格内容可能跨页，需要在合并时，合并成一个表格。

#### 4.6：批量处理

合并完之后，再从【图片目录】读取接下来的5张图片，并启动5个子agent按 4.4–4.6 执行。直到处理完【图片目录】下的所有图片文件。

#### 4.7：检查修正输出结果

按以下步骤review输出的md文档，并修正发现的问题：
1. 【图片目录】下的子agent输出文件是否有内容缺失或格式异常（md文件应与【图片目录】中的图片一一对应，若有缺失，应验证为空白页）。
2. 表格是否有没有对齐的问题，是否有表格内容被拆分成多个表格的情况。
3. 根据标题的编号：
   3.1. 检查是否有标题顺序错误或缺失
   3.2. 检查全文标题 x、x.x、x.x.x、x.x.x.x等标题层级对应的标题等级是否一致。
4. 是否有存在重复的页眉页脚、页码等非内容信息。

#### 4.8：按需提取插图

在 4.7 验证通过后，从各临时md的含图标记中筛选出含图页面，按需从PDF中提取高清插图。采用"多模态定位 → 程序裁剪 → 多模态校验 → 更新md引用"四段式流程：

**命名清洗规则**：4.8 中所有自动生成的目录名与文件名，均先将【输入文件名】/【图名】按文首占位符约定清洗为【清洗后输入文件名】/【清洗后图名】（例如 `SFT 0028-2018 智慧监狱 技术规范` → `SFT_0028-2018_智慧监狱_技术规范`）。

扫描【图片目录】下所有子agent输出的临时md文件，解析末尾的 `<!-- 本页含图: ... -->` 标记（含图标记记录了图片所在PDF页、图名/内容描述），得到含图页面清单。无含图标记的文档可跳过本步骤。

对每个含图页，单独启动一个多模态子agent，做以下操作：

##### 4.8.1：多模态定位与裁剪

1. 读取【图片目录】中对应页码的PNG图片（如 `xxx_10.png`），输出图中目标图形区域的**百分比坐标**（left/top/right/bottom，0~1，左上角为原点、x向右、y向下）。提示子agent：坐标应只覆盖图形本体，**排除上方/下方的正文文字**；若图注紧贴图形可包含图注。
2. 调用脚本 `scripts/crop_images.py` 按坐标裁剪【图片目录】/【对应PNG图片】;并注意：
   - 如果一张图中含多张图片，则多组坐标分别裁剪，生成多张图片。
   - 输出到【输入文件所在目录】/【清洗后输入文件名】.files/ 目录（与主md文档对应、`.files` 后缀的兄弟目录，遵循 Markdown 图文同目录惯例；目录名中的空格等非法字符已按上述规则替换为下划线），命名规则：`<清洗后图名>.png`。

裁剪命令示例：

```bash
python "<skill目录>/scripts/crop_images.py" "【图片目录】/【对应PNG图片】" --bbox "left,top,right,bottom" --output "【输入文件所在目录】/【清洗后输入文件名】.files/<清洗后图名>.png"
```

##### 4.8.2：裁剪结果校验

启动多模态子agent复查【输入文件所在目录】/【清洗后输入文件名】.files/ 下每张裁剪图，检查：
1. 是否混入正文文字；
2. 图形是否完整（未截断）；
3. 图注是否包含；
4. 清晰度。

若不合格，将校验反馈（如"上边界需再下移约X%"）作为修正指令，回到 4.8.1 微调坐标重新裁剪，**每张图最多重试3次**；仍不合格则保留最近一次结果并在日志中标注"裁剪可能不完整，请人工复核"。

##### 4.8.3：将裁剪后的图插入主md文档

将主md文档【输入文件名】.md 中引用该图的位置的链接替换为相对路径：`![图注文字](【清洗后输入文件名】.files/<清洗后图名>.png)`

全部图提取完成后，在【输入文件所在目录】/【清洗后输入文件名】.files/ 目录下生成 `图片提取清单.md`，记录每张图的来源页、坐标、裁剪结果与校验结论，便于追溯。

注意：
- 对开页文档中，若图跨越中缝，定位时按左右半页分别定位，裁剪时用原始页整图坐标，脚本会自动基于整页裁剪，无需预先拆分。
- 图片存放与引用采用 Typora/Pandoc 兼容的 `【清洗后输入文件名】.files/` 兄弟目录约定，目录名与图名中的空格等非法字符统一替换为下划线，md 与图片文件夹可整体拷贝迁移。

#### 4.9：检查修正图片插入结果

按以下步骤review输出的md文档，并修正发现的问题：
1. 【输入文件名】.md中是否还存在 `<!-- 本页含图: ... -->` 标记，若有则说明图片未正确插入。
2. 检查图片的引用路径是否正确，即 `![图注文字](【清洗后输入文件名】.files/<清洗后图名>.png)` 是否正确指向了裁剪后的图片。

针对问题页面执行 4.8.1–4.8.3，重新定位裁剪并更新md引用，直至修正完成。

## 错误处理

**公共**：
- 用户指定的 PDF 不存在、不是 PDF、损坏或无法打开（检测脚本退出码 2），应当抛出错误并提示用户检查输入路径、文件格式。
- 缺少依赖（脚本会提示缺 PyMuPDF/Pillow），按步骤1安装后重跑。

**文本层路线（步骤3）**：
- 检测退出码 1（无文本层/文本极少）时不要强行文本提取，应改走步骤4图片 OCR 路线。
- 检测退出码 3（文本层乱码）时**直接放弃文本层提取**，改走步骤4图片 OCR 路线；extract 脚本对多数页乱码同样以退出码 3 中止且不产出文件，不要绕过守卫强行输出乱码内容。
- extract 脚本报告"校验回退页"属正常兜底（该页回退纯文本输出），交付时说明即可；报告"乱码回退页"时，这些页需按 3.2 导出 PNG 用多模态子agent识别后补齐。

**图片路线（步骤4）**：
- 如果导出后的【图片目录】不存在、为空，或包含非图片文件，或者从图片文件名称判断不是由同一个文件导出，或者使用的模型不支持图片识别的，应当抛出错误并提示用户检查导出结果和使用的模型。
- 如果检测到图片为对开页文档但无法准确识别装订线/中缝位置进行拆分，应当提示用户确认图片是否为对开页扫描件，并建议调整扫描方式或将双页拆分为单页后重新处理。
- 如果 4.8 中定位子agent返回的坐标越界（超出0~1范围）、坐标明显异常（如left>right、top>bottom），或裁剪脚本执行失败，应当抛出错误并提示用户检查定位结果与PDF文件；连续重试3次仍校验不通过的图片，保留最近一次裁剪结果并在日志中标注"请人工复核"。

## 实践经验（图片 OCR 路线，2026-09-10 GBT 42517.1 全流程验证后补充）

文本层路线的踩坑记录见步骤3的"文本层路线要点"与 `references/notes.md`。

1. **依赖安装慢**：国内网络下 pip 默认源可能长时间无响应，直接改用镜像安装（见步骤1）。
2. **子agent偶发不支持图片读取**：并行 OCR 时个别子agent会报"当前模型不支持图片读取（OCR）"，属随机路由问题，**直接重试一次**即可；重试仍失败可由主agent亲自 Read 识别并代写该页临时 md。
3. **主会话 Read 图片被内容指纹去重拦截**：子agent读过某图后，主会话再 Read 同一图片（含复制副本）会返回"same content as previously read"而不给图。绕过方法：用 PIL 把图片**转码为 JPEG**（内容字节变化即绕过指纹）再读。
4. **截断修正优先像素分析而非目测**：校验反馈"某边界需移动X%"按目测比例修正常连错多轮（整页2339px高，5%误差即100+px）。高效做法：用 numpy 对页面图做**行/列深色像素带分析**（`dark = (arr<128).sum(axis=1)`，找连续内容带的精确起止行/列），据真实像素边界构造 bbox，一次到位；图注行、页码行均可由此区分（图注居中宽幅、页码靠左窄幅）。
5. **表内嵌图**：若表格单元格内含示例图（如"典型路面标线示例图"类表格），OCR 子agent会把含图标记写进表格单元格导致渲染异常。合并时应把标记移到表格后方独立成行，单元格内改用"见下方示例图①②"文字指引，并在图名中保留表号（如"表17示例图①"）便于追溯。
6. **子agent批量OCR触发429频率限制**：大批量（几十页以上）并行调度子agent时，默认模型可能中途触发 429 使用量/频率限制（报错含重置时间，可能数小时后才重置）。处理：后续批次给 Agent 调用加 `model: "lite"` 切换到轻量模型即可继续，识别质量对印刷体文档足够；个别子agent空回复不代表失败，先核对临时 md 文件是否已生成再决定是否重试。
7. **长文档合并后先跑"编号完整性对账"再修格式**：保险条款/规范类文档常有"主条款+附加条款"各带一套 8.1.x 定义编号（重复属正常，勿误删）。建议合并后用脚本核对每个编号区间的连续性（缺失/重复清单），并把"表格行形式的编号条目"（`| 8.1.x | 名称 | 定义 |`）统一转换为 `#### 标题 + 段落` 形式，再按编号深度（N.→##、N.N→###、N.N.N→####）全局归一化标题层级；转换表格行时注意 del_idx 必须覆盖所有已转换的原始行，防止残留重复。
8. **429 频率限制的第三条路**：默认模型子agent报 429（"使用量已超出频率限制"）且重置时间遥远时，给 Agent 调用加 `model: "lite"` 参数可立即恢复并行 OCR，无需等待重置、也无需主agent逐页代写；已有部分成果时先 `ls "tmp_【清洗后输入文件名】"/*.md` 核对缺失页清单再补齐。
9. **子agent"完成"但回复为空**：并行批次中个别子agent回复空内容且实际未写出目标 md，不能以回复文本为准，必须以文件清单核对（缺失页重新派发即可）。
10. **含图标记引号类型不确定**：子agent写入的 `<!-- 本页含图: ... -->` 标记中可能使用 ASCII 直引号（U+0022）或中文弯引号（U+201C/U+201D），替换为图片引用前先 grep 原文按实际字符精确匹配，两种引号模式都要兼容。
11. **保险单证类 PDF 的页脚**：保单/回执/凭证页脚常含"打印日期"、流水号、条形码，属非内容信息应删除；但单证正文字段（保险合同号码、生效日等）即使值相同也是内容，删除前须区分位置（页脚独立成行 vs 表格字段行）。
12. **脚注编号链连续性论证**：多页文档（保险条款、标准规范等）的印刷脚注编号通常全文连续（如 1–4、5–9、10–15…）。子agent常把小字号上标误读（漏编号、自编局部编号如 [1][2] 或"注1"）。合并时用连续性核对：前页末条编号+1 应等于后页首条编号，据此反推修正各页编号（如第7页止于4、第9页起点应为10 而非子agent报的13）；对关键/可疑上标，用 PIL 把对应页转码为 JPEG 后主会话读原图核实（见第3条绕指纹方法）。
13. **签章≠插图**：保单、公文、合同类页面中的红色圆形印章（如"保险合同专用章"）、签名、条形码属于签章/防伪要素而非插图，OCR 子agent可能为其添加含图标记，合并与 4.8 时应忽略，不做定位裁剪。
14. **子agent转写字面性错误抽核**：同一文档不同子agent的识别质量波动大，合并时对语义突兀的短语（如"治疗不等于有症"→"治疗不孕症"、"功能性障碍理疗"→"慢性功能障碍治疗"）不要臆改也不要照抄，应转码读原图核实后再定；公式类（如现金价值 n/m）优先按数学自洽性修正。
15. **子agent配额限流（429）的兜底**：并行批次跑到中途可能整批返回 `429 您的使用量已超出频率限制`（并给出数小时后的重置时间）。此时**不要等待**，改由主agent亲自 Read 页面图并 Write 临时 md——主会话通常不占用子agent配额。实测同时并发 10 个子agent可稳定完成，可把批次从 5 提到 10。失败批次的页面务必用文件存在性清单核对（`for i in $(seq -w 1 N); do [ -f ... ] || echo $i; done`），确认哪些页需要自补。
16. **横向（旋转 90°）排版的宽表页**：部分 PDF 把超宽表旋转 90° 印在竖版页上，直接用子agent识别会得到乱码或整页转述。处理：先 `PIL.Image.open(f).convert('RGB').rotate(±90, expand=True)` 再读；**同一份文档内不同页的旋转方向可能相反**（本例第48页需 rotate(-90)、第49/50页需 rotate(+90)），两个方向都要试。旋转后按四宫格切片（左上/左下/右上/右下）放大 2 倍分块识别，避免长表行数被裁掉。
17. **数值转录的自洽性校验（强推荐）**：对利益演示表、现金价值表等数字密集型表格，找出行列间的恒等关系做校验，能立刻发现误读。例：退保金 =（不含生存给付的）年度末现金价值 + 当年度末生存给付；生存给付 = 账户价值 × 领取比例。校验通过的行可信，不通过的回原图放大核对。
18. **合并后的自动化质检脚本（4.7 必做）**：写脚本做四件事，一次性暴露大多数合并缺陷——(a) 按表格块统计每行列数，不一致即为单元格拆分/错位（本例发现"最高职业类别：1级"被塞进相邻单元格、多出孤立 `|`）；(b) 找相邻表格块的空行间隔，间隔=1 行的通常是被分页拆断的同一张表（条款目录、跨页长表）；(c) 校验编号标题层级 `X.`→`##`、`X.Y`→`###`、`X.Y.Z`→`####` 是否与编号深度一致，不一致批量重排；(d) 扫"行尾无标点且下一段以字续接"的跨页断句并合并（如 `### 10.14 无合法有效行` + `### 驶证`）。
19. **中英文引号统一**：中文文档中不同子agent会混用 ASCII `"` 与全角 `“”`。合并后按行处理，`"` 个数为偶数的行按奇偶配对替换为 `“ ”`；**必须跳过含 HTML 注释的行**，否则 `<!-- 本页含图: 名称"别名" -->` 里的引号会与正文错位，导致后续标记匹配失败（4.8.3 替换不到）。建议把引号统一放在 4.8 之后做，或先备份。
20. **4.8 定位用像素带分析而非目测**：对目标图形（流程图、二维码、封面主视觉）先用 numpy 做行/列深色像素带统计（`dark = (arr<200).sum(axis=1)`，找连续内容带的精确起止行/列），据真实像素边界构造 bbox，一次到位。签名类元素需在"上一行正文结束行"与"签名起始行"之间取空隙作为上边界，否则会把上一行正文裁进来（本例第35页首裁混入"申请仲裁或向法院起诉。"，二次微调上边界后才干净）。
21. **印章 vs 签名（对第13条的细化）**：红色圆形印章、条形码确属防伪要素，不做裁剪；但**手写/电子签名**在保单类文档中承载"签署留痕"信息，若子agent已标出可保留并裁剪（本例保留了投保人电子签名与手写签名两处），裁剪时把"投保人电子签名："标签一并纳入，使切图自解释。
