## Workflow：PDF 图片处理流程

本 skill 仅支持一种输入方式：

1. **PDF 文件**：用户直接指定一个 PDF 文件，先执行「步骤0」，将其逐页导出为 PNG 图片，存放在【输入文件路径】/tmp/ 目录下，后续步骤一律从该目录读取图片并处理。

以下统一用【图片目录】指代图片的来源目录，即：

- 【图片目录】=【输入文件路径】/tmp/

### 步骤0：删除【输入文件路径】/tmp/ 目录

检查【输入文件路径】/tmp/ 目录是否存在，若存在则删除该目录及其内容，确保后续步骤中导出的图片不会与旧文件冲突。

### 步骤1：PDF 转 PNG 图片

用户指定 PDF 文件后，先执行本步骤，将 PDF 逐页导出为 PNG 图片：

1. 调用脚本 `scripts/pdf_to_png.py`（位于本 skill 目录下，当前完整路径为 `C:\Users\fhdi2\.workbuddy\skills\pdf-img-to-md\scripts\pdf_to_png.py`），执行命令示例：

   ```bash
   python <skill目录>/scripts/pdf_to_png.py 【输入文件路径】 --dpi 200
   ```

   - 脚本会自动创建【输入文件路径】/tmp/ 目录，图片输出到该目录。
   - 图片命名规则：【文件名】_NN.png（如 report_01.png、report_02.png，页码按总页数自动补零，满足步骤2的前缀判断规则）。
2. 若运行时报错提示缺少 PyMuPDF 依赖，先安装依赖再重新运行：`pip install pymupdf`。
3. 导出完成后，核对【输入文件路径】/tmp/ 目录下 PNG 图片数量与 PDF 页数一致，然后以【输入文件路径】/tmp/ 作为【图片目录】，继续执行步骤2。

注意事项：

- 扫描件建议加 `--dpi 300` 提高识别精度；普通电子版 PDF 用默认 `200` 即可。
- 局部调试可配合 `--start-page` / `--end-page` 仅导出部分页。

### 步骤2：判断【图片目录】下的图片文件由一个pdf文档导出

读取【图片目录】（即【输入文件路径】/tmp/）下的图片文件列表，检查图片是否来自同一份文件（通常命名为【文件名】_01.png、【文件名】_02.png等）。如果图片文件名称不符合规则，或者无法判断是否来自同一份文件，则抛出错误并提示用户检查图片文件是否来自同一份文件。

需要先确定用户使用的大模型具备图片识别能力，否则无法进行图片内容识别。

### 步骤2.1：检测并标记对开页文档

在读取【图片目录】的图片文件列表后，对选取3张图片进行预处理检测，判断是否为扫描的对开页文档（即双页并排扫描）：

- **标记策略**：如果检测到图片为对开页，则在该图片的处理标记中注明"对开页/双页并排"，并记录需要拆分为左页和右页分别识别。
- **兼容处理**：即使用户未明确告知，子agent也应当主动识别图片是否为对开页结构，并据此调整处理策略。 

### 步骤3：创建空文档
在 【输入文件路径】/ 目录下，创建一个空的md文档【输入文件名】.md。

### 步骤4：调用子agent处理文件

从【图片目录】读取图片：启动5个子agent，按照图片名称的排序（从小到大），每个子agent从【图片目录】读取一张图片的内容，并输出到: 【输入文件路径】/tmp/【图片名】.md。

子agent处理时需要注意以下事项：
- 识别图片内容，提取文本、表格、公式等信息，并按原文及原有格式输出到md文件中。
- 识别表格时，尽量保持表格的原有结构和格式，必要时进行格式优化。
- 忽略图片中的水印、页眉页脚、页码等非内容信息。
- **对开页（双页并排）处理**：如果图片属于扫描的对开页文档（即一张图片中包含左右两页内容），需要按以下规则处理：
  - 首先识别图片中的装订线/中缝位置，以此作为左右分页的基准线。
  - 将图片内容拆分为**左页**和**右页**两部分，分别识别。
  - 识别时先读取左页内容（按从左到右、从上到下的阅读顺序），再读取右页内容。
  - 如果左右两页的表格内容存在跨页关联（如表头相同、内容连续），需在输出时进行合并处理，确保表格完整性。
  - 输出到临时md文件时，按左页在前、右页在后的顺序输出，保持文档的原始阅读顺序。

### 步骤5：合并子agent输出

将步骤4的子agent输出的5个【图片名】.md  文件（位于 【输入文件路径】/tmp/），合并到 【输入文件名】.md 文件中，合并时评估是否有表格使用相同的表头等情况，需要进行格式优化。

合并时需要注意以下事项：
- 保持原有的内容顺序，确保合并后的md文档内容完整。
- 不需要补充页码、页眉页脚等非内容信息。
- 对于表格，表格内容可能跨页，需要在合并时，合并成一个表格。


### 步骤6：批量处理

合并完之后，再从【图片目录】（即【输入文件路径】/tmp/）读取接下来的5张图片，并启动5个子agent按步骤4-6执行。直到处理完【图片目录】下的所有图片文件。

### 步骤7：验证输出结果

按以下步骤review输出的md文档，并修正发现的问题：
1. 【输入文件路径】/tmp/ 目录下的子agent输出文件是否有内容缺失或格式异常（md文件应与【图片目录】中的图片一一对应）。
2. 表格是否有没有对齐的问题，是否有表格内容被拆分成多个表格的情况。
3. 根据标题的编号，检查是否有标题顺序错误或缺失，标题的层级是否正确。
4. 是否有存在重复的页眉页脚、页码等非内容信息。

## 输出目录

在用户执行本skill的目录下生成输出文件：

- **主md文档**：根据图片前缀生成的【输入文件名】.md，包含所有图片的OCR内容
- **图片目录**（由步骤1自动生成）：【输入文件路径】/tmp/ 下的【文件名】_NN.png 图片文件
- **临时文件**：位于 `【输入文件路径】/tmp/` 目录下的【图片名】.md 文件（用于子agent处理）
- **日志文件**：记录处理过程、错误信息及性能指标

## 错误处理

如果用户指定的PDF文件不存在、不是PDF、损坏或无法导出图片（含缺少 PyMuPDF 依赖），应当抛出错误并提示用户检查输入路径、文件格式及依赖安装情况。

如果导出后的【图片目录】（【输入文件路径】/tmp/）不存在、为空，或包含非图片文件，或者从图片文件名称判断不是由同一个文件导出，或者使用的模型不支持图片识别的，应当抛出错误并提示用户检查导出结果和使用的模型。

如果检测到图片为对开页文档但无法准确识别装订线/中缝位置进行拆分，应当提示用户确认图片是否为对开页扫描件，并建议调整扫描方式或将双页拆分为单页后重新处理。
